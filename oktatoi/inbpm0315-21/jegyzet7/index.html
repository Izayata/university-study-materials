Kontextus

Eddig úgy ellenőriztük, hogy a programjaink helyesen működnek-e, hogy lefuttattuk őket, és szemmel megnéztük a kiírt eredményt (a múlt órán már egy kicsit tovább mentünk: a HashSet.size() értékét figyeltük). Ez működik, de van egy nagy hátránya: minden egyes alkalommal, amikor változtatunk valamit a kódon, manuálisan kell újra ellenőriznünk, hogy minden még mindig jól működik-e.

Ma két eszközt nézünk meg, amelyek ezen segítenek: a unit tesztet (automatikusan, ismételten lefuttatható ellenőrzés), és a Javadocot (a kód dokumentálása, hogy mások — vagy a jövőbeli mi magunk — az implementáció elolvasása nélkül is tudják, mit csinál egy metódus).

Hirdetés

Unit teszt bevezetés, JUnit 5 IntelliJ-ben

Unit teszt: Egy unit teszt egy külön kódrészlet, amely egyetlen metódus (vagy osztály) viselkedését ellenőrzi, automatikusan, emberi beavatkozás nélkül — és bármikor újra lefuttatható.

Mi a JUnit? A JUnit egy Java tesztelési keretrendszer — ez adja a @Test annotációt és az ellenőrzéshez (assertion) használt segédmetódusokat. Mi az 5-ös verzióját (JUnit Jupiter) használjuk.

JUnit 5 hozzáadása a projekthez (IntelliJ)

Az 1. órán eldöntöttük, hogy nem használunk Mavent/Gradle-t — ez a teszteléshez sem szükséges, az IntelliJ ezt is le tudja kezelni:

  1. Nyissátok meg a Student.java fájlt, álljatok a Student osztály nevére.
  2. Cmd+Shift+T (macOS) / Ctrl+Shift+T (Windows/Linux) → Create New Test.
  3. A felugró ablakban válasszátok a JUnit5-öt a Testing library legördülőből.
  4. Ha az IntelliJ jelzi, hogy a JUnit5 nincs még a projekten ("JUnit5 library not found") — kattintsatok a felkínált Fix/letöltés gombra. Az IntelliJ automatikusan letölti és hozzáadja a szükséges könyvtárat.
  5. Az IntelliJ létrehoz egy StudentTest.java fájlt egy test mappában.

Első teszt: getAverage()

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class StudentTest {

    @Test
    void averageIsCalculatedCorrectly() {
        Student student = new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5});

        double result = student.getAverage();

        assertEquals(4.666666666666667, result, 0.0001);
    }
}

Amit tisztázni kell:

  • @Test: jelzi a JUnit-nak, hogy ez a metódus egy futtatandó teszteset.
  • assertEquals(expected, actual): ellenőrzi, hogy a várt (expected) és a ténylegesen kapott (actual) érték megegyezik-e. Ha nem, a teszt elbukik (piros), és a hibaüzenet megmutatja mindkét értéket.
  • A harmadik paraméter (0.0001) egy tolerancia — double értékek összehasonlításánál szükséges, mert a lebegőpontos aritmetika miatt egy apró kerekítési eltérés is előfordulhat.
  • A teszt metódus neve (averageIsCalculatedCorrectly) leíró — nem test1, hanem elmondja, mit ellenőrzünk.

equals()/hashCode() szerződés tesztelése

A múlt órán println-nel néztük meg, hogy a HashSet hogyan viselkedik a hashCode() javítása előtt és után. Most írjuk meg ugyanezt automatikus tesztként, amit bármikor újra lefuttathatunk: 

import static org.junit.jupiter.api.Assertions.assertNotEquals;

@Test
void equalStudentsAreEqual() {
    Student s1 = new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5});
    Student s2 = new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5});

    assertEquals(s1, s2);
    assertEquals(s1.hashCode(), s2.hashCode());
}

@Test
void differentStudentsAreNotEqual() {
    Student s1 = new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5});
    Student s2 = new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5});

    assertNotEquals(s1, s2);
}
  • Az első teszt mindkét felét ellenőrzi a szerződésnek: nem elég, hogy equals() szerint egyenlők, a hashCode()-juknak is meg kell egyezniük — pontosan ez volt a múlt órai hiba forrása.
  • A második teszt azt biztosítja, hogy a equals() ne mondjon mindenre igent — egy hibásan megírt equals() (pl. return true;) ezen elbukna.
Hirdetés

Tesztek futtatása és értelmezése

  • Egyetlen teszt futtatása: kattintsatok a metódus melletti zöld ▶ ikonra a sorszám mellett.
  • Az egész osztály futtatása: kattintsatok az osztálynév melletti zöld ▶▶ ikonra, vagy jobb klikk a fájlon → Run 'StudentTest'.
  • Zöld eredmény: minden assertEquals/assertNotEquals teljesült.
  • Piros eredmény: legalább egy ellenőrzés elbukott. Az IntelliJ Run panelje megmutatja, melyik teszt bukott el, és mit várt, mit kapott ("expected: X but was: Y").

Próbáljuk ki szándékosan egy hibás elvárt értékkel:

assertEquals(5.0, student.getAverage(), 0.0001);   // szándékosan rossz érték

Futtatás után figyeljétek meg a piros hibaüzenetet, és azt, hogy pontosan megmutatja a különbséget a várt és a tényleges érték között.

Java documentation (Javadoc)

Javadoc: A Javadoc egy speciális megjegyzés-formátum (/** ... */), amellyel egy osztályt, metódust vagy mezőt dokumentálunk — az IDE-k (pl. IntelliJ) ezt megjelenítik, amikor valaki használja az adott metódust, anélkül hogy meg kellene nyitnia annak forráskódját. 

/**
 * Egy hallgatót reprezentál névvel, Neptun-kóddal és jegyekkel.
 *
 * @author Martin Juracskó
 */
public class Student {

    /**
     * Létrehoz egy új hallgatót a megadott adatokkal.
     *
     * @param name       a hallgató neve
     * @param neptunCode a hallgató Neptun-kódja
     * @param grades     a hallgató jegyei
     */
    public Student(String name, String neptunCode, int[] grades) {
        // ...
    }

    /**
     * Kiszámolja a hallgató jegyeinek átlagát.
     *
     * @return a jegyek számtani átlaga
     */
    public double getAverage() {
        // ...
    }
}

Amit tisztázni kell:

  • A Javadoc komment /**-gal kezdődik (két csillag), nem sima /*-gal — ez különbözteti meg egy szokásos blokk-kommenttől.
  • @param — egy paramétert ír le; annyi kell belőle, ahány paramétere van a metódusnak.
  • @return — a visszatérési értéket írja le (konstruktornál és void metódusnál nincs).
  • @author — opcionális, az osztály szerzőjét jelöli.

IntelliJ-s gyorsítás: álljatok egy metódus fölé, gépeljetek be /**, majd nyomjatok Entert — az IntelliJ automatikusan legenerálja a @param/@return sablont a metódus szignatúrája alapján, már csak ki kell tölteni a szöveget.

Megoldások

1. feladat

import static org.junit.jupiter.api.Assertions.assertTrue;

@Test
void graduateStudentSpecialRequirementContainsThesisTopic() {
    GraduateStudent g = new GraduateStudent("Kiss Réka", "GHI789", new int[]{5, 5, 4},
            "Dr. Nagy Péter", "Gépi tanulás alkalmazásai");

    String requirement = g.getSpecialRequirement();

    assertTrue(requirement.contains("Gépi tanulás alkalmazásai"));
}
  • assertTrue(feltétel) — akkor bukik el a teszt, ha a megadott logikai kifejezés false.
  • String.contains(...) — ellenőrzi, hogy egy részlet szerepel-e a szövegben, anélkül hogy a teljes formázott mondatot szóról szóra le kellene másolni a tesztbe.

2. feladat

Ez a feladat nem ad új kódot, hanem egy meglévő teszt szándékos elrontását és a hibaüzenet elolvasását kéri: 

assertEquals(5.0, student.getAverage(), 0.0001);   // szándékosan rossz érték

Futtatás után az IntelliJ Run panelje piros eredményt mutat, valahogy így: 

org.opentest4j.AssertionFailedError: expected: <5.0> but was: <4.666666666666667>
  • Az expected: <5.0> a tesztbe beírt (hibás) elvárt érték.
  • A but was: <4.666666666666667> a metódus ténylegesen visszaadott értéke.

Miután visszaírtátok a helyes 4.666666666666667-et, a teszt újra zöld lesz.

3. feladat

/**
 * Két objektumot akkor tekint egyenlőnek, ha mindkettő {@code Student},
 * és megegyezik a nevük és a Neptun-kódjuk.
 *
 * @param obj az összehasonlítandó objektum
 * @return {@code true}, ha a két objektum egyenlő
 */
@Override
public boolean equals(Object obj) {
    // ...
}

/**
 * A {@link #equals(Object)}-ben használt mezőkkel (név, Neptun-kód)
 * konzisztens hash-kódot ad vissza — enélkül a {@code HashSet}/{@code HashMap}
 * hibásan viselkedne két, egyenlőnek számító hallgatóval (6. óra).
 *
 * @return a hallgató hash-kódja
 */
@Override
public int hashCode() {
    // ...
}

A két Javadoc szándékosan hivatkozik egymásra ({@link #equals(Object)}) — ez is jelzi, hogy a kettő nem írható meg egymástól függetlenül: a hashCode()-nak mindig ugyanazokon a mezőkön kell alapulnia, mint az equals()-nak.

4. feladat

Ha megpróbáljátok megírni a tesztet a jelenlegi equals()-szal:

@Test
void studentAndGraduateStudentWithSameDataAreNotEqual() {
    Student s = new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5});
    GraduateStudent g = new GraduateStudent("Kovács Anna", "ABC123", new int[]{5, 4, 5},
            "Dr. Nagy Péter", "Gépi tanulás alkalmazásai");

    assertNotEquals(s, g);
}

...ez a teszt elbukik! A !(obj instanceof Student) ellenőrzés nem azt vizsgálja, hogy obj pontosan Student-e, hanem hogy is-a Student-e — egy GraduateStudent is instanceof Student (hiszen extends Student), tehát az ellenőrzés átengedi, és mivel a név/Neptun-kód megegyezik, az equals() igazat ad vissza.

A javítás: cseréljük az instanceof ellenőrzést getClass()-ra, ami a pontos osztályt hasonlítja össze, nem az "is-a" viszonyt: 

@Override
public boolean equals(Object obj) {
    if (this == obj) return true;
    if (obj == null || getClass() != obj.getClass()) return false;

    Student other = (Student) obj;
    return this.name.equals(other.name) && this.neptunCode.equals(other.neptunCode);
}

Ezzel a fenti teszt már lefut helyesen (assertNotEquals teljesül), mert s.getClass() (Student) és g.getClass() (GraduateStudent) különböznek, még akkor is, ha g egyébként instanceof Student.

Házi feladat

Ezek a feladatok a 7. órán tanultak (JUnit 5, Javadoc) önálló, otthoni elmélyítésére szolgálnak, a Student hierarchiátokra építve.

1. feladat (Könnyű) — compareTo() tesztelése

Írjatok egy JUnit tesztet, amely ellenőrzi a Student compareTo() (5. óra, Comparable) metódusát:

  • egy hallgató önmagával összehasonlítva 0-t adjon,
  • egy "Anna" nevű hallgató egy "Béla" nevű hallgatóval összehasonlítva negatív értéket adjon (mert ábécésorrendben előrébb van).

2. feladat (Közepes) — AverageGradeComparator tesztelése

Írjatok egy JUnit tesztet, amely két, különböző átlagú Student objektumot hoz létre, és ellenőrzi, hogy az AverageGradeComparator (5. óra) a kisebb átlagú hallgatót helyezi előbbre (negatív compare() eredmény).

3. feladat (Közepes/Haladó) — Javadoc kiegészítés

Írjatok Javadocot a GraduateStudent konstruktorához (@param minden paraméterhez), valamint az AverageGradeComparator compare() metódusához (@param, @return) — ezek még nincsenek dokumentálva.

4. feladat (Haladó) — Az equals()/hashCode() szerződés tulajdonságainak tesztelése

Írjatok teszteket, amelyek a szerződés általános tulajdonságait ellenőrzik, nem csak egy konkrét esetet:

  1. Reflexivitás: egy Student mindig egyenlő önmagával (s.equals(s)).
  2. Szimmetria: ha a.equals(b) igaz, akkor b.equals(a)-nak is igaznak kell lennie.
  3. hashCode konzisztencia: ugyanazon objektum hashCode()-ja kétszer meghívva mindig ugyanazt az értéket adja.
