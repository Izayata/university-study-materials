Absztrakt osztály, interfész, Comparable, Comparator

Kontextus

Eddig a Student és GraduateStudent osztályokkal dolgoztunk, mindkettő konkrét, példányosítható osztály volt. Ma két új eszközt vezetünk be, amelyekkel kényszeríthetjük a leszármazottakat bizonyos viselkedés megvalósítására: az absztrakt osztályt és az interfészt. A végén pedig egy nagyon gyakorlati problémát oldunk meg mindkettő segítségével: hogyan rendezzünk egy Student[] tömböt.

Hirdetés

Absztrakt osztály, absztrakt metódus

Bővítsük a hierarchiánkat: vegyük észre, hogy a GraduateStudent valójában egy speciális hallgató — van neki valami "extra kötelezettsége" a sima hallgatókhoz képest. Vezessünk be egy köztes osztályt, amely ezt a közös tulajdonságot fogalmazza meg, de amelynek önmagában nincs értelme példányosítani (egy "speciális hallgató általában" nem létezik, csak konkrét fajtái).

Absztrakt osztály: Olyan osztály, amelyet nem lehet közvetlenül példányosítani (new-val létrehozni) — csak leszármazottakon keresztül használható.

Absztrakt metódus: Egy metódus, amelynek csak a fejlécét deklaráljuk (nincs törzse, nincs {}), és a leszármazott osztályoknak kötelező megvalósítaniuk. 

public abstract class SpecialStudent extends Student {

    public SpecialStudent(String name, String neptunCode, int[] grades) {
        super(name, neptunCode, grades);
    }

    public abstract String getSpecialRequirement();
}
  • Az abstract kulcsszó az osztálynevén jelzi, hogy SpecialStudent-et nem lehet közvetlenül példányosítani: new SpecialStudent(...) fordítási hiba lenne.
  • A getSpecialRequirement() metódusnak nincs törzse — ez egy ígéret: "minden leszármazott osztálynak meg kell mondania, mi az ő extra kötelezettsége."

Alakítsuk át a GraduateStudent-et úgy, hogy a Student helyett a SpecialStudent-ből származzon (ő is Student, hiszen a SpecialStudent maga is Student-ből öröklődik): 

public class GraduateStudent extends SpecialStudent {

    private String supervisor;
    private String thesisTopic;

    public GraduateStudent(String name, String neptunCode, int[] grades,
                            String supervisor, String thesisTopic) {
        super(name, neptunCode, grades);
        this.supervisor = supervisor;
        this.thesisTopic = thesisTopic;
    }

    @Override
    public String getSpecialRequirement() {
        return "Diplomamunka leadása, téma: " + this.getThesisTopic() + " (témavezető: " + this.getSupervisor() + ")";
    }
}

És vegyünk fel egy második leszármazottat is, hogy lássuk, miért éri meg ez a kényszerítés: 

public class ExchangeStudent extends SpecialStudent {

    private String hostCountry;

    public ExchangeStudent(String name, String neptunCode, int[] grades, String hostCountry) {
        super(name, neptunCode, grades);
        this.hostCountry = hostCountry;
    }

    public String getHostCountry() {
        return hostCountry;
    }

    @Override
    public String getSpecialRequirement() {
        return "Csereprogram teljesítése: " + this.getHostCountry();
    }
}

A lényeg: ha valaki ír egy harmadik SpecialStudent-leszármazottat, és elfelejti megvalósítani a getSpecialRequirement()-et, a kód nem fordul le — az absztrakt metódus kikényszeríti, hogy minden konkrét leszármazott gondoskodjon róla. Ez erősebb garancia, mint egy sima felülírható (de nem kötelező) metódus.

Interfész (általános fogalom)

Interfész: Egy interfész egy szerződés/kontraktus, amely megmondja, milyen metódusokat kell megvalósítania egy osztálynak — de az interfésznek semmilyen saját állapota (mezője) és jellemzően semmilyen implementációja nincs. Egy osztály egyszerre több interfészt is megvalósíthat (implements), szemben az öröklődéssel, ahol csak egy szülőosztály lehet. 

public interface Reportable {
    String getReportLine();
}

Valósítsa meg a Student:

public class Student implements Reportable {
    // ... eddigi mezők, konstruktor, metódusok ...

    @Override
    public String getReportLine() {
        return this.getName() + " - átlag: " + this.getAverage();
    }
}

Absztrakt osztály vs. interfész — a lényegi különbség:

  • Az absztrakt osztálytól örökölünk (extends) — csak egyet lehet, és megkapjuk a közös mezőket és implementált metódusokat is (pl. a SpecialStudent konstruktorát).
  • Az interfészt megvalósítjuk (implements) — többet is lehet egyszerre, de az interfész önmagában nem ad se mezőt, se kész implementációt, csak a "mit kell tudnod" listát.
Hirdetés

Comparable

Most egy nagyon konkrét, beépített interfészt nézünk meg: a rendezéshez való Comparable-t.

Comparable: A java.lang.Comparable<T> interfész egyetlen metódust ír elő: compareTo(T other). Ezt implementálva megmondjuk, mi számít egy Student természetes rendezési sorrendjének. 

public class Student implements Reportable, Comparable<Student> {
    // ...

    @Override
    public int compareTo(Student other) {
        return this.name.compareTo(other.name);
    }
}
  • Egy osztály több interfészt is megvalósíthat egyszerre (itt: Reportable és Comparable<Student>), vesszővel elválasztva.
  • A compareTo visszatérési értéke: negatív, ha this "kisebb" (előrébb van), 0, ha egyenlő, pozitív, ha this "nagyobb" (hátrébb van) a paraméterhez képest. A String.compareTo már pontosan ezt a konvenciót követi ábécésorrendhez, ezért egyszerűen ráépíthetünk.

Comparator

Mi van, ha másképp is szeretnénk rendezni néha — mondjuk átlag szerint, nem név szerint? A compareTo-t nem írhatjuk át kétféleképp egyszerre. Erre való a Comparator.

Comparator: A java.util.Comparator<T> egy külön interfész, amely egy compare(T a, T b) metódust ír elő — ezzel egy alternatív, a természetes rendezéstől független sorrendet tudunk megadni, anélkül hogy a Student osztályt módosítanánk. 

import java.util.Comparator;

public class AverageGradeComparator implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return Double.compare(a.getAverage(), b.getAverage());
    }
}
  • Double.compare(x, y) ugyanazt a negatív/0/pozitív konvenciót követi, mint korábban a compareTo, csak double értékekre.
  • Ezt a Comparator-t külön, tetszőleges számban írhatjuk meg (pl. egy másikat név szerint csökkenő sorrendhez), a Student osztály érintetlen marad.

Tömb rendezése

Most tegyük össze mindent: rendezzük a Student[] tömbünket (a múlt óráról) mindkét módon. 

import java.util.Arrays;

Student[] students = new Student[] {
    new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}),
    new GraduateStudent("Kiss Réka", "GHI789", new int[]{5, 5, 4},
                         "Dr. Nagy Péter", "Gépi tanulás alkalmazásai"),
    new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5}),
};

// Természetes rendezés (Comparable) — név szerint
Arrays.sort(students);
for (Student s : students) {
    System.out.println(s.getReportLine());
}

// Egyedi rendezés (Comparator) — átlag szerint
Arrays.sort(students, new AverageGradeComparator());
for (Student s : students) {
    System.out.println(s.getReportLine());
}
  • Arrays.sort(tomb) — a Comparable (természetes rendezés) alapján rendez. Ehhez a tömb elemtípusának implementálnia kell a Comparable-t — ezért kellett a Student-re rátennünk.
  • Arrays.sort(tomb, comparator) — a megadott Comparator alapján rendez, függetlenül attól, hogy az elemtípus implementálja-e a Comparable-t.

Gyakorlat

  1. Írjatok egy második Comparator-t, amely az ExchangeStudent/GraduateStudent megkülönböztetése nélkül, a Neptun-kód szerint rendez.
  2. Próbáljátok ki, mi történik, ha egy SpecialStudent-et közvetlenül megpróbáltok példányosítani (new SpecialStudent(...)) — figyeljétek meg a fordítási hibát.
  3. Írjatok egy harmadik SpecialStudent-leszármazottat (pl. RepeatingStudent, aki egy tárgyat ismétel) a getSpecialRequirement() megvalósításával, és tegyétek bele a students tömbbe is.
  4. Rendezzétek a tömböt a getSpecialRequirement() hossza szerint (String.length()) egy újabb Comparator-ral.

Megoldások

1. feladat

import java.util.Comparator;

public class NeptunCodeComparator implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return a.getNeptunCode().compareTo(b.getNeptunCode());
    }
}
Student[] students = new Student[] {
        new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}),
        new GraduateStudent("Kiss Réka", "ABC124", new int[]{5, 5, 4},
                "Dr. Nagy Péter", "Gépi tanulás alkalmazásai"),
        new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5}),
};

Arrays.sort(students, new NeptunCodeComparator());

// Egyedi rendezés (Comparator) — neptun kod szerint
System.out.println("Egyedi rendezés (Comparator) — neptun kod szerint");
Arrays.sort(students, new NeptunCodeComparator());
for (Student s : students) {
    System.out.println(s.getNeptunCode());
}

Ez a Comparator nem törődik azzal, hogy a Student éppen GraduateStudent, ExchangeStudent vagy sima Student — mindegyiknek van getNeptunCode()-ja, hiszen ez a Student osztályból öröklődik, tehát a rendezés egyformán működik mindegyikükön.

2. feladat

SpecialStudent s = new SpecialStudent("Teszt Elek", "TST000", new int[]{5});

Ez fordítási hibát ad:

error: SpecialStudent is abstract; cannot be instantiated

A fordító már azelőtt jelzi a hibát, mielőtt a program egyáltalán lefutna — pontosan ez az absztrakt osztály lényege: nem lehet "csak úgy" egy általános SpecialStudent-et létrehozni, csak a konkrét leszármazottjait (GraduateStudent, ExchangeStudent, ...).

3. feladat

public class RepeatingStudent extends SpecialStudent {

    private String repeatedCourse;

    public RepeatingStudent(String name, String neptunCode, int[] grades, String repeatedCourse) {
        super(name, neptunCode, grades);
        this.repeatedCourse = repeatedCourse;
    }

    public String getRepeatedCourse() {
        return repeatedCourse;
    }

    @Override
    public String getSpecialRequirement() {
        return "Tárgyismétlés: " + this.getRepeatedCourse();
    }
}
Student[] students = new Student[] {
    new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}),
    new GraduateStudent("Kiss Réka", "GHI789", new int[]{5, 5, 4},
                         "Dr. Nagy Péter", "Gépi tanulás alkalmazásai"),
    new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5}),
    new RepeatingStudent("Tóth Elemér", "QWE111", new int[]{2, 3, 3}, "Programozás alapjai"),
};

for (Student student : students) {
    if (student instanceof RepeatingStudent) {
        System.out.println(student.describeStudent() + " " + ((RepeatingStudent) student).getSpecialRequirement());
    } else {
        System.out.println(student.describeStudent());
    }

}

4. feladat

public class SpecialRequirementLengthComparator implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return Integer.compare(getRequirementLength(a), getRequirementLength(b));
    }

    private int getRequirementLength(Student student) {
        if (student instanceof SpecialStudent) {
            SpecialStudent special = (SpecialStudent) student;
            return special.getSpecialRequirement().length();
        }
        return 0;
    }
}
Arrays.sort(students, new SpecialRequirementLengthComparator());

for (Student student : students) {
    if (student instanceof RepeatingStudent) {
        System.out.println(student.describeStudent() + " " + ((RepeatingStudent) student).getSpecialRequirement());
    } else {
        System.out.println(student.describeStudent());
    }
}

Fontos tervezési döntés: a students tömb vegyesen tartalmaz sima Student-et és SpecialStudent-leszármazottakat (GraduateStudent, RepeatingStudent, ...) — de a getSpecialRequirement() csak a SpecialStudent-en (és leszármazottain) létezik, sima Student-en nem. Ezért a compare() egy segédmetódust (getRequirementLength) használ, amely instanceof-fal ellenőrzi, hogy az adott hallgató SpecialStudent-e: ha igen, lekérdezi a hosszt; ha nem (sima Student), 0-t ad vissza — mintha "nem lenne extra kötelezettsége". Enélkül a compare() megpróbálná meghívni a getSpecialRequirement()-et egy sima Student-en is, ami nem fordulna le (a metódus ott nem létezik).

Puffer (~30 perc)

Kérdések, illetve további gyakorlási idő azoknak, akik lassabban haladnak — az absztrakt osztály és az interfész közti különbség sokaknak elsőre elvont, érdemes rá időt hagyni.

Házi feladat

Ezek a feladatok az 5. órán tanultak (absztrakt osztály/metódus, interfész, Comparable, Comparator, tömb rendezése) önálló, otthoni elmélyítésére szolgálnak. Az első két feladat a Student hierarchiátokra épül, a másik kettő egy teljesen új, önállóan felépített hierarchiát kér — ez utóbbi azt teszteli, hogy a fogalmakat egy ismeretlen helyzetben is alkalmazni tudjátok, nem csak a már ismert Student kódot bővítitek.

1. feladat (Könnyű) — Új interfész: Gradable

Írjatok egy Gradable nevű interfészt, egyetlen boolean isPassing() metódussal. Valósítsátok meg a Student osztályban úgy, hogy akkor adjon true-t, ha a hallgató átlaga legalább 2.0.

2. feladat (Közepes) — Rendezés a jegyek száma szerint

Írjatok egy új Comparator<Student> osztályt (pl. GradeCountComparator néven), amely a hallgatókat a letett jegyek száma (grades.length) szerint rendezi. Próbáljátok ki egy vegyes Student[] tömbön Arrays.sort-tal.

3. feladat (Közepes/Haladó) — Önálló hierarchia: Shape

Építsetek fel nulláról egy kis hierarchiát:

  • egy absztrakt Shape osztályt, egyetlen absztrakt metódussal: double getArea(),
  • egy Circle extends Shape osztályt (radius mezővel), amely megvalósítja a getArea()-t (Math.PI * radius * radius),
  • egy Rectangle extends Shape osztályt (width, height mezőkkel), amely szintén megvalósítja a getArea()-t (width * height).

Próbáljátok meg közvetlenül példányosítani a Shape-et — figyeljétek meg a fordítási hibát.

4. feladat (Haladó) — Shape rendezése terület szerint

Tegyétek a Shape-et Comparable<Shape>-é, úgy hogy a compareTo a getArea() alapján hasonlítson össze két alakzatot. Hozzatok létre egy Shape[] tömböt, benne vegyesen Circle és Rectangle példányokkal, és rendezzétek Arrays.sort-tal terület szerint növekvő sorrendbe.
