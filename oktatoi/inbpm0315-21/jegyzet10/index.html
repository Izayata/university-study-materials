Kontextus

Az elmúlt hetekben kétszer is írtunk egy egész, külön nevesített osztályt, csak azért, hogy megvalósítsunk egyetlen metódust: az 5. órán az AverageGradeComparator-t, a 8. órán pedig egy Executable-t az assertThrows-hoz. Mindkétszer megjegyeztük, hogy van egy rövidebb mód is — ma megnézzük, mi az.

Hirdetés

Funkcionális interfész, lambda alapszintaxis

Funkcionális interfész: Egy interfész, amelynek pontosan egy absztrakt metódusa van. A Comparator<T> (egyetlen absztrakt metódusa: compare) és a JUnit Executable (egyetlen absztrakt metódusa: execute) is ilyenek — csak eddig nem neveztük meg ezt a tulajdonságukat.

Lambda kifejezés: Egy funkcionális interfész megvalósítása tömör, név nélküli formában, egy külön osztály megírása helyett. 

(paraméterek) -> törzs

Nézzünk egy vadonatúj, egyszerű példát, mielőtt visszatérnénk a régi kódunkhoz. A Runnable egy funkcionális interfész (void run()): 

Runnable greeting = () -> System.out.println("Szia!");
greeting.run();   // kiírja: Szia!
  • A () a paraméterlista (itt nincs paraméter).
  • A -> választja el a paramétereket a törzstől.
  • Ha a törzs egyetlen kifejezés, nem kell {} és return — ha több utasításból áll, akkor igen: () -> { ...; return ...; }.

Reveal: AverageGradeComparator lambdává alakítása

Emlékezzünk vissza az 5. órára — egy teljes, külön osztályt írtunk:

public class AverageGradeComparator implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return Double.compare(a.getAverage(), b.getAverage());
    }
}

// használat:
Arrays.sort(students, new AverageGradeComparator());

Mivel a Comparator<Student> egy funkcionális interfész (egyetlen absztrakt metódusa: compare(Student a, Student b)), ugyanez lambdával: 

Comparator<Student> byAverage = (a, b) -> Double.compare(a.getAverage(), b.getAverage());

Arrays.sort(students, byAverage);
// vagy akár közvetlenül, külön változó nélkül:
Arrays.sort(students, (a, b) -> Double.compare(a.getAverage(), b.getAverage()));

Ami eltűnt: a public class AverageGradeComparator implements Comparator<Student> { @Override ... } köré épülő teljes osztályváz — csak a lényeg (a két paraméter és az összehasonlítás logikája) maradt.

Reveal: assertThrows Executable-je lambdává

A 8. órán ezt írtuk, mert a lambdákat még nem ismertétek:

assertThrows(InvalidGradeException.class, new Executable() {
    @Override
    public void execute() throws Throwable {
        new Student("X", "Y", new int[]{6});
    }
});

Az Executable is funkcionális interfész (egyetlen absztrakt metódusa: execute()), tehát: 

assertThrows(InvalidGradeException.class, () -> new Student("X", "Y", new int[]{6}));

Ugyanaz a viselkedés, egyetlen sorban — az anonim osztály teljes new Executable() { @Override public void execute() ... } váza eltűnt.

Hirdetés

Metódusreferencia (::)

Ha egy lambda csak továbbad egy már létező metódusnak, tovább rövidíthetjük metódusreferenciával. 

import java.util.function.Function;

// lambda, ami csak meghívja a getName()-t:
Function<Student, String> nameGetter = s -> s.getName();

// ugyanaz metódusreferenciával:
Function<Student, String> nameGetterRef = Student::getName;
  • Student::getName azt jelenti: "vedd az s paramétert, és hívd meg rajta a getName()-t" — pontosan azt, amit a lambda expliciten leírt, csak rövidebben.
  • Ez akkor működik, ha a lambda egyetlen, meglévő metódushívásból áll, semmi extra logika nincs benne.

Ezt mindjárt hasznosítjuk is a stream-es map-nél.

Stream alapok: filter, map, forEach, collect

Stream: A Stream egy olyan API, amellyel egy kollekció (pl. List) elemein egymás után láncolt műveleteket (szűrés, átalakítás, stb.) végezhetünk, tömören, ciklusok kézi megírása nélkül. 

import java.util.List;
import java.util.stream.Collectors;

List<Student> graduateStudents = students.stream()
        .filter(s -> s instanceof GraduateStudent)
        .collect(Collectors.toList());

List<String> names = students.stream()
        .map(Student::getName)
        .collect(Collectors.toList());

students.stream()
        .filter(s -> s.getAverage() >= 4.0)
        .forEach(s -> System.out.println(s.getReportLine()));

Amit tisztázni kell:

  • .stream(): bármely List-ből (vagy más kollekcióból) elindítja a stream-et.
  • filter(predicate): csak azokat az elemeket engedi tovább, amelyekre a lambda true-t ad vissza.
  • map(function): minden elemet átalakít valami mássá (itt: Student → String név) — itt használtuk a Student::getName metódusreferenciát.
  • forEach(consumer): minden elemen végrehajt egy műveletet (jellemzően a lánc végén, mert nem ad vissza új stream-et).
  • collect(Collectors.toList()): a stream végeredményét visszaalakítja egy List-té.

Stream aggregáció: count, átlag, összeg

long graduateCount = students.stream()
        .filter(s -> s instanceof GraduateStudent)
        .count();

double overallAverage = students.stream()
        .mapToDouble(Student::getAverage)
        .average()
        .orElse(0.0);

int totalGradeCount = students.stream()
        .mapToInt(s -> s.getGrades().length)
        .sum();
  • count(): megszámolja, hány elem maradt a lánc végén.
  • mapToDouble/mapToInt: a map-hez hasonló, de kifejezetten primitív double/int értékekre specializált stream-et ad vissza — ez teszi elérhetővé az .average(), .sum() metódusokat.
  • .average(): egy OptionalDouble-t ad vissza (lehet, hogy a stream üres volt) — az .orElse(0.0) ad egy alapértéket, ha nincs eredmény.

Stream + rendezés lambdával

List<Student> sortedByAverage = students.stream()
        .sorted(Comparator.comparing(Student::getAverage))
        .collect(Collectors.toList());
  • Comparator.comparing(keyExtractor): egy beépített segédmetódus, amely egy metódusreferenciából (vagy lambdából) készít egy teljes Comparator-t — még rövidebb, mint amit korábban kézzel írtunk.

Gyakorlat

  1. Válasszatok egy korábbi órán írt, névvel ellátott osztályt vagy anonim osztályt (pl. a Reportable egy megvalósítása, ha van ilyenetek), és alakítsátok át lambdává, ha az adott interfész funkcionális.
  2. Írjatok egy stream pipeline-t, amely a students listából kiszűri az ExchangeStudent-eket, kigyűjti a nevüket egy List<String>-be, és kiírja őket.
  3. Számítsátok ki stream-mel, hány hallgatónak van 4.5 fölötti átlaga (filter + count).
  4. Rendezzétek a students listát Comparator.comparing(Student::getName)-nel, stream-en keresztül.

Házi feladat

Ezek a feladatok a 10. órán tanultak (funkcionális interfész, lambda, metódusreferencia, stream-ek) önálló, otthoni elmélyítésére szolgálnak, a Student hierarchiátokra építve.

1. feladat (Könnyű) — Saját funkcionális interfész

Írjatok egy saját Validator funkcionális interfészt, egyetlen boolean isValid(Student s) metódussal. Hozzatok létre belőle egy lambdával megvalósított példányt, amely akkor ad true-t, ha a hallgató átlaga legalább 3.0. Próbáljátok ki néhány hallgatón.

2. feladat (Közepes) — Összes jegy száma stream-mel

Számítsátok ki stream-mel, hogy a students listátokban összesen hány jegy szerepel (minden hallgató minden jegyét összeszámolva). Segítség: mapToInt(s -> s.getGrades().length), majd .sum().

3. feladat (Közepes/Haladó) — Rendezés Neptun-kód szerint, metódusreferenciával

Rendezzétek a students listát stream-mel, Neptun-kód szerint, Comparator.comparing(Student::getNeptunCode) használatával, majd írjátok ki az eredményt egy forEach(System.out::println) hívással (ez is egy metódusreferencia — gondoljátok át, milyen lambdát vált ki).

4. feladat (Haladó) — Legjobbak, csökkenő sorrendben

Építsetek egy stream pipeline-t, amely:

  1. kiszűri azokat a hallgatókat, akiknek az átlaga legalább 4.0,
  2. csökkenő átlag szerint rendezi őket (nézzetek utána a Comparator reversed() metódusának),
  3. collect-tel List<Student>-té alakítja,
  4. végül kiírja mindegyiket.
