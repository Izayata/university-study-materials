Kollekciók: lista és rendezése, set, map

Magas szintű programozási nyelvek 2 (INBPM0315-21) · 6. labor gyakorlat · Frissítve: 2026-09-19

Tematika

  • Lista (ArrayList)

Kontextus

A 2. órán a tömbökkel dolgoztunk — azoknak rögzített a mérete, létrehozáskor eldől, és utólag nem változtatható. Ma megnézzük a kollekciókat (java.util csomag): olyan adatszerkezeteket, amelyek futás közben nőni és zsugorodni tudnak. Három fő fajtájukat nézzük meg: List, Set, Map.

Hirdetés

Lista (ArrayList)

Lista (List): Sorrendtartó, tetszőleges méretű gyűjtemény — hasonlít a tömbre, de futás közben bővíthető/csökkenthető, és nincs előre rögzített mérete. 

import java.util.ArrayList;
import java.util.List;

List<Student> students = new ArrayList<>();

students.add(new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5}));
students.add(new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}));
students.add(new GraduateStudent("Kiss Réka", "GHI789", new int[]{5, 5, 4},
                                  "Dr. Nagy Péter", "Gépi tanulás alkalmazásai"));

System.out.println(students.size());   // 3, nem .length!

for (Student s : students) {
    System.out.println(s.getReportLine());
}

Amit tisztázni kell:

  • List<Student> — a List egy interfész, az ArrayList pedig annak egy konkrét megvalósítása. Ez ismerős mintázat: a múlt órán a Comparable/Comparator is interfészek voltak, amiket konkrét osztályok/metódusok valósítottak meg.
  • students.size() — metódus, nem mező, ezért van zárójel — szemben a tömb .length-jével, ami mező.
  • add, get(i), remove(i) — a lista bővítése, egy elem lekérdezése index alapján, egy elem eltávolítása.
  • A GraduateStudent simán belefér egy List<Student>-be — pontosan ugyanaz a polimorfizmus, amit a 4. órán a Student[] tömbnél láttunk.

Lista rendezése

A múlt órán a Student osztályt Comparable<Student>-té tettük (név szerint rendez), és írtunk egy külön AverageGradeComparator-t (átlag szerint rendez). Ez a munka listákra is működik, nem csak tömbökre — semmit nem kell újraírni. 

import java.util.Collections;

Collections.sort(students);              // természetes rendezés (Comparable) — név szerint
students.sort(new AverageGradeComparator());   // egyedi rendezés (Comparator) — átlag szerint
  • Collections.sort(list) — a Collections segédosztály statikus metódusa, a Comparable alapján rendez. Ez a List-es megfelelője a múlt heti Arrays.sort(tomb)-nak.
  • list.sort(comparator) — magán a listán meghívható metódus, egyedi rendezéshez. Ez a List-es megfelelője az Arrays.sort(tomb, comparator)-nak.
Hirdetés

Halmaz (HashSet) — az equals()/hashCode() szerződés

Halmaz (Set): Egy Set nem enged duplikátumokat — ha egy már benne lévő elemmel egyenlő (equals() szerint) elemet próbálunk hozzáadni, az nem kerül be újra.

Próbáljuk ki:

import java.util.HashSet;
import java.util.Set;

Set<Student> uniqueStudents = new HashSet<>();

uniqueStudents.add(new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5}));
uniqueStudents.add(new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5}));

System.out.println(uniqueStudents.size());   // meglepetés: 2, nem 1!

Pedig a 3. órán megírt equals() szerint ez a két Student egyenlő (ugyanaz a name és neptunCode)! Mi történt?

A hashCode() szerepe: A HashSet (és a legtöbb hash-alapú gyűjtemény) nem hívja meg azonnal az equals()-t minden egyes benne lévő elemre — az túl lassú lenne sok elemnél. Ehelyett előbb a hashCode() alapján egy "rekeszbe" (bucketbe) sorolja az elemeket, és csak az azonos rekeszben lévő elemeket hasonlítja össze equals()-szal. Ha két, equals() szerint egyenlő objektumnak különböző a hashCode()-ja, a HashSet sosem fogja őket összehasonlítani — külön rekeszbe kerülnek, és úgy tűnik, mintha különbözőek lennének.

A szabály (equals/hashCode szerződés): Ha felülírjuk az equals()-t, kötelezően felül kell írnunk a hashCode()-ot is, ugyanazokra a mezőkre alapozva — máskülönben a hash-alapú gyűjtemények (HashSet, és később HashMap) hibásan fognak viselkedni.

Javítsuk a Student-et:

import java.util.Objects;

@Override
public int hashCode() {
    return Objects.hash(name, neptunCode);
}
  • Objects.hash(...) egy beépített segédmetódus, amely a megadott mezőkből konzisztens hashCode-ot generál — ugyanazokat a mezőket kell megadni neki, amelyeket az equals() is összehasonlít.

Futtassuk újra az előző kódot:

System.out.println(uniqueStudents.size());   // most már helyesen: 1

Map (HashMap)

Map: Egy Map kulcs-érték párokat tárol — nem index, hanem egy kulcs alapján érjük el az értékeket. 

import java.util.HashMap;
import java.util.Map;

Map<String, Student> studentsByNeptun = new HashMap<>();

studentsByNeptun.put("ABC123", new Student("Kovács Anna", "ABC123", new int[]{5, 4, 5}));
studentsByNeptun.put("XYZ789", new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}));

Student found = studentsByNeptun.get("ABC123");
System.out.println(found.getReportLine());

System.out.println(studentsByNeptun.containsKey("QWE111"));   // false

for (Map.Entry<String, Student> entry : studentsByNeptun.entrySet()) {
    System.out.println(entry.getKey() + " -> " + entry.getValue().getReportLine());
}

Amit tisztázni kell:

  • put(kulcs, érték) — beszúr vagy felülír egy párt.
  • get(kulcs) — visszaadja a kulcshoz tartozó értéket, vagy null-t, ha nincs ilyen kulcs.
  • containsKey(kulcs) — megmondja, létezik-e a kulcs, null-ellenőrzés nélkül.
  • entrySet() — az összes kulcs-érték párt bejárhatóvá teszi egy ciklusban.

Fontos: a HashMap a kulcsok tárolásához ugyanúgy a hashCode()/equals() párost használja, mint a HashSet — ha Student-et (és nem String-et) használnánk kulcsként, pontosan ugyanaz a szabály vonatkozna rá, amit az imént a Set-nél megbeszéltünk.

Gyakorlat

  1. Építsetek egy List<Student>-et, benne legalább egy Student, egy GraduateStudent és egy ExchangeStudent objektummal, majd rendezzétek mindkét módon (Collections.sort, majd list.sort(new AverageGradeComparator())).
  2. Reprodukáljátok a HashSet-es hibát: adjatok hozzá két, azonos adatú Student-et egy HashSet-hez a hashCode() felülírása előtt, ellenőrizzétek a size()-t, majd írjátok meg a hashCode()-ot, és ellenőrizzétek újra.
  3. Építsetek egy Map<String, Student>-et a students listátokból (ciklussal, put-tal), és kérdezzetek le belőle hallgatókat Neptun-kód alapján.
  4. Debuggerrel (2. óra!) lépegessetek végig a HashSet.add() hívásokon, és nézzétek meg a Variables panelen, hogyan változik a halmaz mérete a hashCode() javítása előtt és után.

Megoldások

1. feladat

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

List<Student> students = new ArrayList<>();
students.add(new Student("Nagy Béla", "XYZ789", new int[]{3, 4, 2}));
students.add(new GraduateStudent("Kiss Réka", "GHI789", new int[]{5, 5, 4},
        "Dr. Nagy Péter", "Gépi tanulás alkalmazásai"));
students.add(new ExchangeStudent("Tóth Elemér", "QWE111", new int[]{4, 5, 4}, "Németország"));

// Természetes rendezés (Comparable) — név szerint
Collections.sort(students);
for (Student s : students) {
    System.out.println(s.getReportLine());
}

System.out.println("---");

// Egyedi rendezés (Comparator) — átlag szerint
students.sort(new AverageGradeComparator());
for (Student s : students) {
    System.out.println(s.getReportLine());
}

Ugyanaz a két rendezési mód (Comparable, AverageGradeComparator), amit az 5. órán a Student[] tömbre írtunk — most List<Student>-en hívjuk meg, és semmit nem kellett hozzáírni.

2. feladat

import java.util.HashSet;
import java.util.Set;

Set<Student> uniqueStudents = new HashSet<>();
uniqueStudents.add(new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5}));
uniqueStudents.add(new Student("Tóth Elemér", "QWE111", new int[]{5, 5, 5}));

System.out.println(uniqueStudents.size());   // hashCode() felülírása előtt: 2

Miután megírtátok a hashCode()-ot a Student-ben (a leckében látott Objects.hash(name, neptunCode) alapján), ugyanez a kód: 

System.out.println(uniqueStudents.size());   // hashCode() felülírása után: helyesen 1

3. feladat

import java.util.HashMap;
import java.util.Map;

Map<String, Student> studentsByNeptun = new HashMap<>();
for (Student s : students) {
    studentsByNeptun.put(s.getNeptunCode(), s);
}

Student found = studentsByNeptun.get("GHI789");
System.out.println(found.getReportLine());

Itt szándékosan az 1. feladatban épített students listát használjuk — nem kell újra, elölről felépíteni, csak végig kell menni rajta egy ciklussal, és minden elemet betenni a Map-be a Neptun-kódja alapján.

4. feladat

Ez a feladat a debuggeren keresztül figyelendő meg, nincs önálló "megoldó" kód — az alábbiakat várjuk, ha lépésről lépésre végigmentek rajta:

  • Tegyetek egy breakpointot a 2. feladat első uniqueStudents.add(...) sorára, és indítsátok Debug módban.
  • hashCode() felülírása előtt: az első add() után a Variables panelen a uniqueStudents mérete 1. Lépjetek tovább a második add()-ra — mivel a két Student objektum hashCode()-ja (az Object-től örökölt, memóriacím-alapú alapértelmezés) különböző, a HashSet két külön "rekeszbe" teszi őket. A méret 2-re nő, annak ellenére, hogy equals() szerint egyenlők lennének — az equals()-t a HashSet ilyenkor meg sem hívja, mert a két elem sosem kerül azonos rekeszbe.
  • hashCode() megírása után: futtassátok újra ugyanígy, lépésenként. Most a két objektum hashCode()-ja megegyezik, tehát ugyanabba a rekeszbe kerülnek — a HashSet emiatt már meghívja az equals()-t is, ami igazat ad, így a második add() nem növeli a méretet: a Variables panelen a uniqueStudents mérete 1 marad.

Házi feladat

Ezek a feladatok a 6. órán tanultak (List, Set, Map) önálló, otthoni elmélyítésére szolgálnak, a Student hierarchiátokra építve. Ciklusokkal/feltételekkel oldjátok meg őket — a lambdás/stream-es rövidítések majd a 10. órán jönnek.

1. feladat (Könnyű) — Hallgató eltávolítása Neptun-kód alapján

Írjatok egy metódust, amely egy List<Student>-ből és egy Neptun-kódból kiindulva eltávolítja azt a hallgatót, akinek ez a Neptun-kódja (ha van ilyen). Ügyeljetek arra, hogy ne magán a bejáráson belül hívjatok remove()-ot — először keressétek meg az indexet egy ciklussal, és csak utána, a ciklus lezárása után távolítsátok el.

2. feladat (Közepes) — Egyedi értékek egy Set-tel

Tegyük fel, hogy minden Student-nek van egy major (szak) mezője (ha még nincs, vegyétek fel gyorsan, néhány példaértékkel). Írjatok egy metódust, amely egy List<Student>-ből egy Set<String>-be gyűjti az egyedi szakok neveit (duplikátumok nélkül), és írjátok ki őket.

3. feladat (Közepes/Haladó) — Csoportosítás típus szerint

Írjatok egy metódust, amely egy List<Student>-et típus szerint csoportosít egy Map<String, List<Student>>-be — a kulcs legyen "Student", "GraduateStudent" vagy "ExchangeStudent" (az instanceof segítségével döntsétek el, melyik hallgató melyik csoportba tartozik). Írjátok ki csoportonként a hallgatók számát.

4. feladat (Haladó) — Jegyek gyakorisága

Írjatok egy metódust, amely egy List<Student> összes hallgatójának összes jegyét végignézve elkészít egy Map<Integer, Integer>-t, amely megmondja, az egyes jegyértékek (1–5) hányszor fordulnak elő összesen. (Segítség: ha egy jegy még nincs a Map-ben, tegyétek be 1-gyel; ha már van, növeljétek meg az eddigi értéket eggyel.)
