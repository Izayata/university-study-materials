Kontextus

A 6. órán felépítettünk egy List<Student>-et — de amint a program leáll, ez az egész adat eltűnik. Ma megtanuljuk, hogyan mentsük fájlba, és hogyan olvassuk vissza onnan. Ez a mai óra a szokásosnál egy kicsit sűrűbb: két különböző API-t nézünk meg (a klasszikusat és a modernet), úgyhogy a puffer idő ma rövidebb lesz a végén.

Hirdetés

Klasszikus java.io: írás és olvasás, manuális close()

Állomány (fájl): A program futása után is megmaradó adattároló egység a lemezen.

Mentsük ki a hallgatóinkat egy szöveges fájlba, soronként név;neptunkód;jegy1,jegy2,jegy3 formátumban: 

import java.io.BufferedWriter;
import java.io.FileWriter;
import java.io.IOException;

public void saveStudentsClassic(List<Student> students, String fileName) throws IOException {
    BufferedWriter writer = null;
    try {
        writer = new BufferedWriter(new FileWriter(fileName));
        for (Student s : students) {
            writer.write(toLine(s));
            writer.newLine();
        }
    } finally {
        if (writer != null) {
            writer.close();
        }
    }
}

private String toLine(Student s) {
    StringBuilder gradesText = new StringBuilder();
    int[] grades = s.getGrades();
    for (int i = 0; i < grades.length; i++) {
        gradesText.append(grades[i]);
        if (i < grades.length - 1) {
            gradesText.append(",");
        }
    }
    return s.getName() + ";" + s.getNeptunCode() + ";" + gradesText;
}

Amit tisztázni kell:

  • FileWriter/BufferedWriter: a FileWriter közvetlenül a fájlba ír, a BufferedWriter egy hatékonyabb, pufferelt réteget tesz köré — ezért csomagoljuk egymásba.
  • throws IOException: a fájlműveletek IOException-t (checked, 8. óra!) dobhatnak — pl. ha nincs jogosultságunk írni. Ezt vagy kezelnünk kell, vagy tovább kell adnunk.
  • A finally-ben lévő close(): kötelezően be kell zárnunk a fájlt, különben az erőforrás (fájlkezelő) "nyitva marad" — ezt hívjuk erőforrás-szivárgásnak (resource leak). A finally biztosítja, hogy ez kivétel esetén is lefusson.

Az olvasás hasonlóan néz ki:

import java.io.BufferedReader;
import java.io.FileReader;

public List<String> readLinesClassic(String fileName) throws IOException {
    List<String> lines = new ArrayList<>();
    BufferedReader reader = null;
    try {
        reader = new BufferedReader(new FileReader(fileName));
        String line;
        while ((line = reader.readLine()) != null) {
            lines.add(line);
        }
    } finally {
        if (reader != null) {
            reader.close();
        }
    }
    return lines;
}

Miért try-with-resources?

A fenti kód működik, de van egy rejtett veszélye: ha a null-ellenőrzést elfelejtenénk, vagy ha a close() hívás maga is kivételt dobna, könnyen hibázhatunk — és minden egyes fájlműveletnél újra le kell írnunk ezt a finally/null-ellenőrzés mintázatot.

Try-with-resources: Ha egy erőforrás (pl. BufferedWriter, BufferedReader) implementálja az AutoCloseable interfészt, a try (...) zárójeles részében megnyitva automatikusan bezáródik a blokk végén — kivétel esetén is —, kézi close() hívás nélkül. 

public void saveStudentsClassic(List<Student> students, String fileName) throws IOException {
    try (BufferedWriter writer = new BufferedWriter(new FileWriter(fileName))) {
        for (Student s : students) {
            writer.write(toLine(s));
            writer.newLine();
        }
    }
}

Nincs többé finally, nincs null-ellenőrzés, nincs kézi close() — a try (...) zárójelben megnyitott writer automatikusan bezáródik, amint a blokk véget ér (akár normálisan, akár kivétellel).

Hirdetés

Modern NIO.2: Files, Path

A fenti minta így is sokat gépeltet velünk soronkénti írásnál/olvasásnál. A modern java.nio.file.Files osztály erre kényelmesebb, egylépéses metódusokat ad. 

import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public void saveStudentsNio(List<Student> students, String fileName) throws IOException {
    List<String> lines = new ArrayList<>();
    for (Student s : students) {
        lines.add(toLine(s));
    }
    Files.write(Path.of(fileName), lines);
}

public List<String> readLinesNio(String fileName) throws IOException {
    return Files.readAllLines(Path.of(fileName));
}
  • Path.of(fileName): egy fájl elérési útját reprezentálja (nem magát a tartalmat).
  • Files.write(path, lines): egyetlen hívással kiírja a lines lista minden elemét, soronként — nincs szükség kézi BufferedWriter-re vagy try-with-resources-re, a Files osztály ezt belsőleg elintézi.
  • Files.readAllLines(path): egyetlen hívással beolvassa az összes sort egy List<String>-be.
  • Mindkettő továbbra is IOException-t dobhat (checked) — ez nem változott, csak a kód sokkal rövidebb lett.

Állománykezelés: exists, delete

Path path = Path.of("students.txt");

if (Files.exists(path)) {
    System.out.println("A fájl létezik, beolvasás...");
    List<String> lines = Files.readAllLines(path);
} else {
    System.out.println("A fájl még nem létezik.");
}

Files.deleteIfExists(path);
  • Files.exists(path): megmondja, létezik-e a fájl, mielőtt megpróbálnánk olvasni belőle (elkerülve egy felesleges kivételt).
  • Files.deleteIfExists(path): törli a fájlt, ha létezik; ha nem létezik, nem dob hibát (szemben a Files.delete(path)-tal, ami ilyenkor kivételt dobna).

Összerakás: Student lista mentése és betöltése

Most kössük össze mindent: mentsük ki, majd olvassuk vissza a List<Student>-et — a visszaolvasásnál a 8. órai InvalidGradeException is előkerül, hiszen a sorokból új Student objektumokat építünk a konstruktoron keresztül. 

public List<Student> loadStudents(String fileName) throws IOException, InvalidGradeException {
    List<Student> result = new ArrayList<>();
    List<String> lines = Files.readAllLines(Path.of(fileName));

    for (String line : lines) {
        String[] parts = line.split(";");
        String name = parts[0];
        String neptunCode = parts[1];
        String[] gradeParts = parts[2].split(",");

        int[] grades = new int[gradeParts.length];
        for (int i = 0; i < gradeParts.length; i++) {
            grades[i] = Integer.parseInt(gradeParts[i]);
        }

        result.add(new Student(name, neptunCode, grades));
    }

    return result;
}

Meghívva:

try {
    List<Student> loaded = loadStudents("students.txt");
    for (Student s : loaded) {
        System.out.println(s.getReportLine());
    }
} catch (IOException e) {
    System.out.println("Nem sikerült beolvasni a fájlt: " + e.getMessage());
} catch (InvalidGradeException e) {
    System.out.println("Hibás jegy a fájlban: " + e.getMessage());
}

Két külön catch ág kell, mert két, egymástól független ok miatt hiúsulhat meg a betöltés: vagy a fájllal van baj (IOException), vagy az adat tartalmával (InvalidGradeException) — és a két esetben más-más hibaüzenetet érdemes adnunk a felhasználónak.

Gyakorlat

  1. Mentsétek ki a students listátokat (6. óra) Files.write-tal egy students.txt fájlba, majd olvassátok vissza loadStudents-szel, és ellenőrizzétek, hogy ugyanazokat az adatokat kaptátok vissza.
  2. Töröljétek a fájlt Files.deleteIfExists-szel, majd Files.exists-szel ellenőrizzétek, hogy tényleg eltűnt.
  3. Rontsatok el kézzel egy sort a fájlban (pl. írjatok bele egy 6-os jegyet), és futtassátok újra a betöltést — figyeljétek meg, hogy az InvalidGradeException ágon keresztül kapunk értelmes hibaüzenetet, nem egy nyers NumberFormatException-t vagy összeomlást.
  4. Alakítsátok át a klasszikus (nem try-with-resources-es) írási metódust úgy, hogy a finally-ben lévő close() hívást szándékosan kihagyjátok — debuggerrel (2. óra!) figyeljétek meg, hogy a program lefut, de a fájl esetenként nem íródik ki teljesen, mielőtt a program véget érne.

Puffer (~20 perc)

Ma rövidebb a puffer, mert sok az anyag — ha nem jut mindenre idő, a Files.exists/delete rész a legkönnyebben áttehető a jövő heti óra elejére bemelegítésként.

Házi feladat

Ezek a feladatok a 9. órán tanultak (klasszikus java.io, try-with-resources, NIO.2, állománykezelés) önálló, otthoni elmélyítésére szolgálnak.

1. feladat (Könnyű) — Sorok számozva

Írjatok egy programot, amely Files.write-tal kiír egy tetszőleges, legalább 5 soros szöveges fájlt (pl. egy bevásárlólistát), majd Files.readAllLines-szal visszaolvassa, és sorszámozva írja ki mindegyik sort (1. <sor tartalma>, 2. <sor tartalma>, ...).

2. feladat (Közepes) — Hozzáfűzés felülírás nélkül

A Files.write(path, lines) alapból felülírja a fájlt. Nézzetek utána (pl. a hivatalos Java dokumentációban) a StandardOpenOption.APPEND opciónak, és írjatok egy metódust, amely egy új hallgatósort hozzáfűz a students.txt fájl végéhez, a meglévő tartalom törlése nélkül. Ellenőrizzétek Files.readAllLines-szal, hogy a régi sorok megmaradtak, és az új a végén jelent meg.

3. feladat (Közepes/Haladó) — Sorok száma try-with-resources-szel

Írjatok egy countLines(String fileName) metódust, amely klasszikus BufferedReader-t használ, try-with-resources-szel (ne kézi close()-lal), és visszaadja, hány sorból áll a megadott fájl.

4. feladat (Haladó) — Hibatűrő betöltés

Az órai loadStudents metódus az első hibás sornál megáll, és az egész betöltést meghiúsítja. Írjatok egy loadStudentsResilient(String fileName) metódust, amely:

  • soronként próbálja meg feldolgozni a fájlt,
  • ha egy adott sor feldolgozása közben InvalidGradeException vagy NumberFormatException keletkezik, kihagyja azt a sort (nem áll le), és megjegyzi, hány sort kellett kihagyni,
  • a végén visszaadja a sikeresen beolvasott hallgatók listáját, és kiírja, hány sort hagyott ki hiba miatt.

Segítség: a try/catch-nek a ciklus belsejében, soronként kell lennie, nem a teljes ciklus körül.
